# Dependências de PRODUÇÃO. Runner de testes não entra aqui — ver
# requirements-dev.txt e a decisão D-Deploy-5 no CLAUDE.md.
#
# Versões pinadas em `==` de propósito: com `>=`, um rebuild meses depois puxa
# breaking change de FastAPI ou Pydantic e o deploy quebra sem ninguém ter
# tocado no código. Para atualizar, suba a versão aqui e rode a suíte.
fastapi==0.139.2
uvicorn==0.51.0
sqlalchemy==2.0.51
pydantic==2.13.4

# Postgres em produção (D-Vercel-2). `psycopg` v3, não `psycopg2-binary`, que é
# legado. O extra `[binary]` traz a lib compilada e evita exigir toolchain de C
# no build da função serverless.
psycopg[binary]==3.3.4

# Schema é responsabilidade do Alembic nos dois ambientes (D-Vercel-6). Fica em
# produção, e não em dev, porque `alembic upgrade head` roda contra o banco
# real — não é ferramenta de teste.
alembic==1.19.1

# Autenticação (D-Auth-4). Uma biblioteca para os dois lados: RS256 para
# verificar o ID token do Google e HS256 para assinar o cookie de sessão. O
# `PyJWKClient` embutido usa `urllib` da stdlib, então nenhum cliente HTTP novo
# entra em produção.
#
# O extra `[crypto]` traz `cryptography`, necessária para RS256. É wheel grande
# e pesa no cold start — mitigado por construção: RS256 só roda no login, e
# toda requisição seguinte valida um HMAC local.
pyjwt[crypto]==2.15.1
